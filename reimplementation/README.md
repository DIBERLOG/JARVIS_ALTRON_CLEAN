# Новое ядро ALTRON

`command-engine` теперь подключён к голосовому приложению и интерфейсу через
совместимый слой `jarvis-core`. Это не только отдельный пример и не переименование:
загрузка команд, подбор действия, план исполнения, запись настроек и хранение
предыдущих кадров микрофона перенесены в новый Rust-модуль.

Модуль не импортирует `jarvis-core`, GUI, модели речи или старый алгоритм сравнения.
Он использует стандартную библиотеку, Serde/JSON, TOML и tempfile. Версии зависимостей
зафиксированы на используемых проектом версиях: миграция не обновляет сторонние модели
и остальные библиотеки приложения.

## Что уже заменено

- `catalog.rs`: чтение пакетов, устойчивый порядок, отчёт об ошибках отдельных пакетов.
- `matching.rs`: точные варианты, параметры, обращение «Джарвис», Unicode,
  ограниченное приближённое сопоставление и неоднозначность. Противоположные действия
  вроде «открой»/«закрой» не считаются опечатками друг друга.
- `dispatch.rs`: построение плана действия без его запуска; проверка пути программы
  и скрипта. Перезапуск и выключение не выбираются приблизительно.
- `process.rs`: прямой запуск программы с отдельными аргументами, без неявного
  `cmd /C` или `sh -c`. Если нужен сценарий оболочки, он должен быть явно описан
  как запуск самой оболочки; существующие команды PowerShell работают так же.
- `persistence.rs`: блокировка между процессами, чтение актуальных настроек и
  атомарная замена файла. Повреждённый файл не сбрасывается в настройки по умолчанию;
  неизвестные новой/старой версии поля сохраняются.
- `audio_history.rs`: ограниченный буфер звука перед командой, без деления на ноль.

Интерфейс работает с прежними именами команд и форматами сообщений. Файл `app.db`,
ключи настроек, данные личного центра и парольное хранилище не перенесены в другие
каталоги. Выбранный пользователем голос S2 не подменяется. Готовые MP3, распознавание,
разговорный режим и действия Lua подключены через совместимые адаптеры.

## Проверки

Из корня репозитория:

```powershell
cargo test -p altron-command-engine -p jarvis-core -p jarvis-app -p jarvis-gui --offline --locked -j 2
cargo build -p jarvis-app -p jarvis-gui --offline --locked -j 2
```

На Windows библиотека `lib/windows/amd64` должна быть доступна линковщику, как и
при прежней сборке приложения. Подключённое ядро проверено вместе с адаптерами:
74 автоматических теста проходят, включая 435 уникальных вариантов команд
на ru/en/ua. 13 проверок сети, локальных моделей и физического звука остаются
явно отключёнными по умолчанию — их успешность не заявляется.

Проверка уже запущенного голосового процесса:

```powershell
powershell -NoProfile -File tools/kernel_smoke.ps1
```

Добавление `-CheckCommands` проверяет выполнение «спасибо» и передачу
«открой центр». Оно воспроизводит подтверждение и открывает раздел центра,
но не изменяет настройки, заметки, пароли или состояние окон Windows.

## Граница этой миграции

Заменены перечисленные службы ядра, но НЕ переписаны целиком приложение,
интерфейс, Lua-пакеты, IPC, драйверы микрофона, распознаватели, синтезаторы
и сторонние модели. Совместимый слой сохраняет существующие типы данных,
плагины и дополнительный распознаватель намерений; новый маршрутизатор не
даёт ему переопределять неоднозначные или отрицательные команды.

Это поэтапная техническая миграция. Она сама по себе не отменяет лицензии
оставшегося кода, записей, образов и моделей и не доказывает независимость
всего продукта. Разработчик видел прежний код; строгий clean-room процесс
не заявляется.

Рабочая сборка до переключения и копия настроек сохранены локально отдельно
от репозитория. Подробности и ограничения отката — в `docs/CORE_MIGRATION.md`.
