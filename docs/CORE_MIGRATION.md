# Подключение ядра ALTRON — 4 октября 2026

## Применённая схема

Приложение и GUI сохраняют внешние интерфейсы. `jarvis-core/src/commands.rs`
стал адаптером к `altron-command-engine`: преобразует текущие манифесты и
результаты нового маршрутизатора в прежние типы и передаёт планы действия
в доступные компоненты. `db.rs` делегирует хранение новому модулю.
`audio_buffer.rs` содержит только совместимое имя нового буфера.

Голосовое приложение сначала использует новый маршрутизатор. Существующий
распознаватель намерений остаётся дополнительным компонентом для фраз, не
попавших в каталог. Он не обходит неоднозначность, отрицание и запрет
приблизительного выбора команд перезапуска. Личный центр продолжает получать
текст, включая номера новостей, названия, длительности и уточнения.

## Откат

Если после пользовательской проверки обнаружится регрессия:

1. Закрыть только голосовое приложение и GUI этой сборки.
2. Запустить прежние EXE из папки резервной копии. Там находятся их ресурсы.
3. Они прочитают актуальные данные из прежнего пользовательского каталога:
   формат настроек и личного центра не менялся.

НЕ заменять актуальный `app.db` файлом `app.db.backup` автоматически: иначе
можно потерять изменения, сделанные после резервного копирования. Копия
настроек нужна только для согласованного восстановления конкретных данных.

## Результат проверки текущей сборки

Оба EXE пересобраны и запущены из `target/debug`. В журнале подтверждены
активация ядра 0.1.0, загрузка 14 пакетов, инициализация микрофона и Vosk,
подключение GUI к голосовому процессу.

Локальная проверка `kernel_smoke.ps1 -CheckCommands` подтвердила ping/pong,
чтение состояния микрофона, успешное исполнение `jarvis_thanks` через новое
ядро и передачу команды открытия центра по прежнему протоколу.
Данные центра, ключи API и выбор голоса совпадают с резервной копией;
хеш парольного хранилища до и после проверки совпал. Старые EXE сохранены
вместе с ресурсами и соседними DLL, необходимыми для запуска на этой машине.

## Что не доказано этой проверкой

Тесты проверяют маршрутизацию, совместимость, хранилище, обработку аудиокадров,
Lua-контекст и текущие сценарии центра. Они не подтверждают все внешние
сервисы и качество звука на конкретных колонках. Не запускались реальные
команды перезагрузки, выключения и сворачивания окон в автоматических тестах.

Перенос нескольких служб ядра не равен замене всего исходного проекта.
Оставшиеся компоненты и модели сохраняют свои условия использования.
