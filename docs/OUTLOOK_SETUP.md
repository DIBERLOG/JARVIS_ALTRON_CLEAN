# Почта Outlook в JARVIS

Раздел «Почта Outlook» поддерживает личные Outlook.com/Hotmail и рабочие Microsoft 365.
Используется официальный Microsoft Graph и вход с кодом устройства. Пароль почты и client secret
приложению не нужны. Без регистрации приложения Microsoft настоящий вход не работает.

## Подключение

1. Откройте [Microsoft Entra admin center](https://entra.microsoft.com/).
2. **App registrations → New registration**. Назовите приложение `JARVIS Outlook`.
3. Выберите **Accounts in any organizational directory and personal Microsoft accounts**.
   Redirect URI для device code flow оставьте пустым.
4. Скопируйте **Application (client) ID** из Overview. Это публичный идентификатор,
   не секретный ключ. Вставьте его в раздел JARVIS «Почта Outlook».
5. **Authentication → Advanced settings → Allow public client flows → Yes**, сохраните.
6. **API permissions → Add a permission → Microsoft Graph → Delegated permissions**:
   `User.Read`, `Mail.ReadWrite`, `Mail.Send`, `offline_access`.
   Application permissions не нужны. Client secret не создавайте.
7. В JARVIS нажмите **Получить код входа**, откройте Microsoft по ссылке и введите код.
   Убедитесь, что на странице Microsoft указано именно ваше зарегистрированное приложение.
8. Войдите в нужный аккаунт и подтвердите доступ. Рабочая организация может требовать
   согласие администратора или блокировать device code flow политиками безопасности.

Если у аккаунта нет права регистрации приложений, нужна помощь администратора Entra/доступ
к каталогу с разрешённой регистрацией. Наличие личной почты не гарантирует наличие такого права.

## Доступные команды

| Команда | Действие |
| --- | --- |
| «Джарвис, открой почту» | Открывает раздел Outlook |
| «Обнови почту» / «Проверь почту» | Получает последние 50 входящих |
| «Открой второе письмо» | Показывает письмо с номером 2 текущего списка |
| «Прочитай первое письмо» | Озвучивает отправителя и тему, полный текст показывает на экране |
| «Напиши письмо» | Запрашивает полный адрес, затем тему и текст |
| «Продолжить письмо» | Продолжает после ручного ввода адреса на экране |
| «Ответь на письмо» | Готовит **новое** письмо отправителю с темой Re:, без threading |
| «Сохрани черновик» | Сохраняет в черновиках Outlook, не отправляет |
| «Отправь письмо» | Запрашивает проверку получателя и содержания |
| «Да, отправить» | Отправляет только предварительно проверенный текст |
| «Отмена» | Отменяет голосовой шаг/подтверждение; письмо не отправляется |

Адрес надёжнее ввести вручную. Для диктовки английского адреса поддерживаются слова
«собака» и «точка». Имена контактов без полного адреса пока не поддерживаются.
Номера соответствуют полному текущему списку и сохраняются при локальной фильтрации.
Обновление списка может изменить номера — всегда проверяйте выбранное письмо.

## Безопасность и ограничения первой версии

- Токены доступа и обновления остаются в памяти backend, не передаются интерфейсу и не
  сохраняются на диск. После полного закрытия GUI нужно войти снова. Публичный Client ID
  сохраняется локально, чтобы не вводить его повторно.
- Полученные письма и несохранённый редактор остаются в памяти до закрытия приложения или
  отключения аккаунта. После сохранения черновик хранится на стороне Microsoft.
- Текст входящих отображается как текст, без выполнения HTML, скриптов и команд из письма.
  Внешние картинки не загружаются. Содержимое не отправляется в DeepSeek/Ollama автоматически.
- Существующая история голосовых запросов/диагностический журнал могут содержать продиктованные
  фразы. Не диктуйте секреты; при использовании почты учитывайте общие настройки истории JARVIS.
- Подтверждение отправки привязано к подготовленному тексту, действует две минуты и используется
  один раз. Редактирование отменяет подтверждение. Таймаут не вызывает повторную отправку:
  сначала проверьте «Отправленные» в Outlook, чтобы не создать дубликат.
- Ответ Microsoft `202 Accepted` означает принятие к отправке, **не подтверждение доставки**.
- В первой версии поиск локальный среди 50 последних входящих. Вложения, весь архив,
  адресная книга, настоящий reply-thread и календарь Outlook пока не подключены.
- Открытие письма не изменяет его статус прочтения. Обновление запускается явно, не постоянно.

## Ошибка AADSTS90072 при входе в Azure Portal

Если сообщение называет приложение **Azure Portal** и каталог, например **Phoenix**,
это ошибка доступа к каталогу Microsoft, а не ошибка подключения почты JARVIS.
Личный аккаунт Microsoft (`live.com`), даже зарегистрированный на адрес Gmail,
не получает автоматически доступ к каталогу организации или право регистрации приложений.

1. Выйдите из портала и откройте https://entra.microsoft.com в приватном окне браузера.
   Войдите нужным аккаунтом. Приватное окно убирает старый выбор аккаунта, но не выдаёт права.
2. Если доступны несколько каталогов, переключитесь на свой в настройках каталогов портала.
3. Если нужен именно этот каталог, попросите его администратора добавить ваш аккаунт
   и предоставить право регистрации приложения либо зарегистрировать приложение для вас.
   Если собственного доступного каталога нет, сначала потребуется его настройка через Microsoft;
   не следует считать, что любой личный аккаунт уже имеет такой каталог.

После получения доступа зарегистрируйте приложение с поддержкой аккаунтов любых организаций
и личных аккаунтов Microsoft, следуя инструкции выше. В JARVIS нужен **Application (client) ID
вашего приложения**, не идентификатор Azure Portal из сообщения об ошибке.
Эта интеграция подключает почтовый ящик Outlook/Microsoft 365, не почту Gmail.
